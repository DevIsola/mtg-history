# Styling architecture: Astro + SCSS

The MTG History site uses **Sass modules for stylesheet organization**, **runtime CSS
custom properties** for the light/dark design tokens, and **Astro-scoped SCSS** for
components. This transition is designed to preserve the existing visual treatment,
not automatically make rendering faster or improve accessibility.

## Ownership

- `src/styles/global.scss` is the single global entrypoint imported by
  `src/layouts/BaseLayout.astro`. `@use` module order is deliberate: reset,
  tokens, foundation, reading, theme, support, characters, exploration, events,
  discovery, interactive explorers. Only move modules if screenshots and
  accessibility tests prove cascade equivalence.
- `src/styles/_tokens.scss` owns the default CSS custom properties and responsive
  `--site-header-height`. `src/styles/_theme.scss` owns the dark-mode overrides.
  Favor `var(--paper)`, `var(--ink)`, `var(--gold)`, etc. for themeable properties;
  Sass variables are compiled away and cannot switch themes at runtime.
- `src/styles/_breakpoints.scss` owns Sass viewport constants. Use
  `@use "../styles/breakpoints" as bp;` in component styles and
  `@media (max-width: bp.$small)`; do not introduce arbitrary new breakpoint
  values when an established breakpoint is appropriate. Keep content-driven
  breakpoints when necessary, documenting new values.
- Global Sass partials are reserved for shared foundations and **legacy page-level
  rules**. Move rules into component-scoped styles incrementally, preserving DOM
  behavior, CSS specificity, and MDX content. Do not globally rename selectors
  or scope styles that intentionally affect slotted/MDX content without tests.
- Components owning markup should own their styles in `<style lang="scss">`.
  Astro scopes these by default. Keep nesting shallow (prefer at most two levels);
  avoid IDs and deep descendant chains. Prefer class selectors or `:where()` to
  minimize specificity, and do not use `:global` without documenting intent.
- Retain semantic HTML, visible focus styles, keyboard controls, reduced-motion
  accommodations and `[hidden]` semantics. SCSS does not establish accessibility
  on its own. Validate mobile and desktop, light and dark modes.

## Dependencies and checks

Dart Sass is a **development dependency** for Astro/Vite to compile `.scss` and
`<style lang="scss">`. Tailwind is not installed. After applying this patch,
run `pnpm install --lockfile-only`, then `pnpm install --frozen-lockfile` and
`pnpm run verify && pnpm exec playwright test`. `check:styles` guards the global
order, reset, central token ownership, Sass dependency and scoped component
examples. The lockfile is regenerated by pnpm rather than hand-edited.

When adding new components, use component-scoped SCSS and CSS custom property
references first; use global partials only for intentional site-wide selectors.

## Component ownership audit (phase 1)

`SiteFooter.astro` now owns its selectors (`.site-footer`, `.footer-grid`,
`.footer-brand`, `.footer-links`, `.footer-legal`) and its 680px breakpoint.
`_foundation.scss` remains responsible for the shared `.page-shell` layout;
that selector must stay global because multiple components consume it.
The `check:styles` gate prevents the migrated footer selectors from returning
into the foundation. Continue moving one cohesive component at a time; avoid
migrating selectors that intentionally style MDX content or child Astro
components unless their cross-boundary rules are accounted for explicitly.

For new components, use semantic BEM-like class names; keep Sass nesting shallow,
prefer CSS custom properties for runtime themes, and retain focus and reduced-
motion behaviors. Reserve global selectors for reset, layout primitives, and
intentionally cross-component or document-level rules. Test both themes at 390px
and 1280px after every ownership migration.

### Dependency build permissions

Sass introduces `@parcel/watcher` as a transitive native dependency. pnpm's
strict build-script policy requires an explicit decision. This repository grants
`@parcel/watcher` only (`pnpm-workspace.yaml`: `allowBuilds`), rather than turning
off the global safety check or approving all dependencies. Review changes to
build permissions during code review and keep the policy committed for CI.
If pnpm has previously ignored this build, rerun `pnpm install --frozen-lockfile`
and, if needed, `pnpm rebuild @parcel/watcher`. pnpm 11+ uses `allowBuilds`;
older pnpm major versions should be aligned before changing the policy format.
